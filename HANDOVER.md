# Продолжение работы над desk-mcp

Рабочая заметка для агента. Читай её целиком, потом начинай с раздела «Следующая задача».
Если контекст сессии длинный и начались повторяющиеся ошибки в вызовах инструментов — читай
этот файл первым, он заменяет переписку.

## 1. Что это и где

| Что | Значение |
| --- | --- |
| Проект | MCP-сервер управления рабочим столом Windows |
| Локально | `C:\Users\DigitalJesus\.minimax\workspace\desk-mcp` |
| GitHub | `https://github.com/DigitalDog1/desk-mcp` (публичный, Apache-2.0) |
| Ветка | `main`, рабочее дерево должно быть чистым перед началом |
| Теги | `v1.0.0` … `v1.3.0`; `1.4.0` готовится и **не опубликован** (в npm пакета нет: `registry.npmjs.org/desk-mcp` отдаёт 404, имя свободно) |
| Размер | server.mjs 1343, worker.ps1 1874, uia-native.cs 916, smoke.mjs 316, bench-tokens.mjs ~160 |
| Инструменты | 42 (`server.registerTool`) |

Назначение: дать модели агента глаза (UIA → MSAA → CDP → OCR) и руки (ввод через WinAPI)
для нативного рабочего стола Windows. Ноль внешних бинарных зависимостей — Node плюс
встроенный в Windows PowerShell. Это осознанная фича, не случайность: отказ от неё,
например ради SharpDX, ломает главный козырь (установка через `npm install` без Visual C++
Build Tools, Python и компиляции нативных модулей).

## 2. Мгновенный старт


### Окна из агентской сессии не видны на десктопе

`Start-Process powershell -File examples\demo-app.ps1` из bash поднимает процесс, но
окна на пользовательском десктопе не появляется: агент работает в другой сессии.
Рабочий путь: `Win+R` через `computer_key`, затем `computer_type` с командой и
`return`. `computer_launch` с `C:\Windows\...\powershell.exe` режет политика
безопасности («protected Windows path»), поэтому диалог Run надёжнее.

Обратное тоже верно: **ffmpeg `-f gdigrab` из агентской сессии десктоп видит**,
кадр не чёрный. Проверено кадром, а не на веру.

Видео для README снято так: захват области окна `940x640` со смещением 60,60,
`draw_mouse=1` (курсор в кадре и неподвижен, это и есть доказательство), подписи
`drawtext` с `enable='between(t,...)'` по шагам сценария, кодирование
`libvpx-vp9 -crf 32`. Remotion для этого не нужен: он рендерит видео из
React-кода и захвата экрана не умеет.

### Формы ответа, о которых спотываешься

- `computer_read_screen` возвращает `{ windows: [...], elementsScanned, backend }`.
  У узла окна ключ **`name`**, не `title`, дети лежат в **`children`**.
- `computer_clipboard_get` возвращает `{ text, length }`, не строку.
- `computer_find` возвращает `{ count, elements }`.

### Как снимать демо для README (рабочая схема)

1. Перезапустить демо-окно с чистым логом, курсор положить в поле лога.
2. **Первым проходом снимать дёшево**: `libx264 -preset ultrafast -crf 16`. Кодировать
   VP9 во время прогона нельзя: CPU забивается, UIA-вызовы упираются в бюджет 8 с,
   breaker блокирует окно, и в кадр попадает пустое состояние при «успешном» отчёте
   скрипта. Проверено дважды.
3. Демо на 9 шагов это ~30 с чистого времени плюс паузы, а не 18 с. Считать не
   надо: `examples/demo.mjs` печатает `(+Xs)` в каждом шаге.
4. **Вторым проходом** сжать (`setpts=0.714*PTS`, это 1.4 раза) и наложить подписи
   `drawtext` с `enable='between(t,...)'`, границы взять из распечаток шагов,
   делённые на 1.4. Итог 24 с, 263 КБ.

Третье число — пропуски. Пропуск означает, что какое-то окно на машине не ответило на
UI Automation (Steam, 1С, старый WPF держат COM-вызов). Это свойство чужого приложения,
а не дефект, и прогон от этого не краснеет. Если провалов больше нуля — это настоящая
поломка, чинить до релиза.

Гонять воркер напрямую (сессия MCP держит старый воркер, список тулов собирается при
старте, поэтому новые тулы в живых вызовах не появятся до перезапуска):

```powershell
$dir = 'C:\Users\DigitalJesus\.minimax\workspace\desk-mcp'
$in = Join-Path $dir '_t_in.txt'; $out = Join-Path $dir '_t_out.txt'; $err = Join-Path $dir '_t_err.txt'
$reqs = @(@{ id = 1; tool = 'read_screen'; args = @{ title = 'Проводник'; maxDepth = 5 } })
$lines = foreach ($r in $reqs) { $r | ConvertTo-Json -Depth 14 -Compress }
[System.IO.File]::WriteAllLines($in, @($lines), (New-Object System.Text.UTF8Encoding($false)))
$p = Start-Process powershell -ArgumentList '-NoProfile','-ExecutionPolicy','Bypass','-File',"$dir\worker.ps1" `
     -RedirectStandardInput $in -RedirectStandardOutput $out -RedirectStandardError $err -WindowStyle Hidden -PassThru -Wait
foreach ($l in (Get-Content $out -Encoding UTF8)) {
  ([System.Text.Encoding]::UTF8.GetString([System.Convert]::FromBase64String($l.Substring(4).Trim()))) | ConvertFrom-Json | ConvertTo-Json -Depth 10 -Compress
}
```

Формат ответа воркера — строка `B64:<base64 от JSON>`, где JSON `{id, ok, data|error}`.
Первая строка — `id: 0`, `ready: true`.

Временные файлы создавать только с префиксом `_t_`, `_d_`, `_s_` в каталоге проекта и
удалять через `rm -- "полный путь"`. Все такие префиксы уже есть в `.gitignore`.

## 3. Состояние проекта

### Закрыто и проверено замерами

- **Circuit breaker для UI Automation.** Бюджет 8 с, после зависания ключ
  `инструмент|окно` блокируется на 90 с. Блокировка поокноная: одно приложение не роняет
  всё. Через него идут `read_screen`, `element_at`, `find`, `invoke`, `set_value`,
  `select_text`, `verify`.
- **Нативный C#-слой UIA** (`uia-native.cs`): STA-пул с очередью, отменяемый таймаут,
  перерождение зависшего потока. Таймаут 1512 мс при бюджете 1500, следующий вызов 43 мс
  на новом потоке (TID 19 → 21). Обход 147 мс против 1014 мс на окне qBittorrent.
- **Общий дедлайн на весь вызов.** Раньше `ensure()` ставил таймер только после себя,
  пауза 30 с превращала бюджет 8 с в 30 931 мс. Сейчас тот же шторм — максимум 2 012 мс.
- **`computer_batch` перенесён с воркера на сервер** и идёт по одному шагу, поэтому
  UIA-шаги проходят через тот же breaker. Раньше пачка обходила защиту целиком.
- **Деградация UIA → MSAA → OCR** в `read_screen`: если оба дерева доступности пусты,
  берётся OCR области окна с полями `backend`, `degraded`, `origin`, `via`.
- **`invoke` / `set_value` / `select_text` отказывают на `enabled=false`.** `InvokePattern`
  на неактивном элементе в Windows молча ничего не делает и не бросает исключение: серая
  кнопка «Копировать» в Paint возвращала `ok: true`, а буфер обмена не менялся.
- **CDP-слой подтверждён на живом сайте**: `computer_browser_tree` вернул селектор
  `body:nth-child(2) > a:nth-child(9)`, `computer_browser_eval` — кириллицу без потерь,
  `computer_browser_click` по `a[href*='iana']` дал `verified: true` и реальный переход
  с `example.com` на `iana.org`. Мышь при этом не двигалась ни разу.
- **npm-пакет собирается и поднимает нативный слой.** Тарбол установлен в отдельный
  каталог, `DESK_UIA_DIAG=1` даёт в stderr
  `UIA-DIAG: RunTree(6000, ...) -> ok=True TID=18 10мс`, то есть STA-пул живой
  именно из установленного пакета, а не из клона.
- **Живые прогоны:** Paint (рисование, заливка, текст, диалог сохранения),
  Counter-Strike: Source (de_dust2: обзор в обе стороны и по вертикали, стрельба),
  Блокнот (`set_value` корректно отказывается там, где писать нечем),
  демо-окно `examples/demo-app.ps1` (`set_value` и `invoke` через паттерны,
  `verify_state satisfied`, буфер обмена после `InvokePattern`).
- **Дельты в `computer_read_screen`** (`mode`, `since`). Замер: 12386 токенов у первого
  `auto`, 38 у повторов на пяти из шести окон, то есть в 327 раз меньше. Повтор со
  старым токеном честно возвращает полный вид: сравнивать с базой, которой у
  вызывающего больше нет, нельзя.
- **`computer_wait_element`**: appear/disappear/state, desiredState, экспоненциальная
  пауза. Таймаут это `satisfied: false` с `reason: timeout`, а не ошибка.
- **`computer_select`**: ComboBox 404 мс, вкладка 95 мс, отказ на элементе без
  паттернов выбора идёт как `PatternUnavailable`, а не как «вариант не найден».
- **`computer_read_table`**: 6x4 за 89-91 мс, 331 токен, заголовки процитированы
  корректно. Первая строка читается как заголовок по соглашению: признака
  «это заголовок» у `TablePatternInformation` в .NET нет, проверено рефлексией.
- **`computer_polyline`**: проверено не словами. Посторонний сэмплер снимал курсор и
  состояние кнопки каждые 8 мс: кнопка физически была зажата 175 мс, отклонение
  курсора от заданной ломаной 0 пикс, 9 из 10 вершин задеты, в Paint нарисовался
  один замкнутый многоугольник без разрывов.
- **`DESK_DISABLE_TOOLS`**: 46 инструментов против 43 при `computer_click,
  computer_*_text, computer_read_table`. Прямой вызов отбит на уровне MCP, batch
  отказывает по имени, список уходит в stderr при старте.
- **`npm run bench:full`** снимает живые окна и печатает, где подход проигрывает.
  Главный вывод прогона: нефильтрованное дерево дороже картинки в 3-15 раз, обход
  дерева медленнее снимка в 3-5 раз, OCR полосы дешевле чтения окна в 6-9 раз.
  Старое утверждение в README было верным только для отфильтрованного случая.
- **Коды ошибок доходят до клиента.** Это чинилось отдельно: `server.mjs` на границе
  с воркером брал `msg.error` и выбрасывал `msg.code`, то есть вся машиночитаемая
  часть отказа исчезала. Проверено сквозным вызовом через MCP-клиент, не только
  на уровне PowerShell.
- **smoke.mjs вырос с 49 до 68 проверок.** Новые сценарии: дельты (включая чужой
  токен), `wait_element` на таймауте и на состоянии, `read_table` и `select` на живом
  демо-окне, девять отказов по схеме и по кодам, отключение инструментов на втором
  сервере с переменной окружения.

### Наблюдения, которые нельзя выводить заново

- **Цена чтения измерена, «дерево дешевле скриншотов» это полуправда.** Поиск
  одного элемента дешевле картинки того же окна в 9.7-147 раз (15-160 токенов
  против 688-4864). Полное дерево местами **дороже** картинки в 8.5 раза
  (Discord: 18765 против 2205 токенов). `interactiveOnly` роняет дерево Discord
  до 1280. Честный кадр для README: «look up the element, do not ship the
  window». Таблица пересобирается `node bench-tokens.mjs`.
- **Локализованная Windows ломает примеры.** UIA отдаёт `Закрыть`, `Развернуть`,
  `Свернуть`, `Системное меню`, поэтому элементы ищутся по `automationId`.
- **OCR халтурный по построению.** `ZX-4471-8820` читается как `zx-=v-882C`.
- **В C# 5 лямбда не видит локальную переменную, объявленную ниже неё.** Из-за
  этого первый вариант `demo-app.ps1` не компилировался: `btnRefresh` ссылался на
  `list`, объявленный после. Объявления контролов, на которые ссылаются
  обработчики, поднимаются выше.

1. **`npm publish` требует владельца.** `npm whoami` даёт ENEEDAUTH, callback-сервер npm
   из агентской сессии не поднимается (порт 8099 не слушался). Тарбол
   `desk-mcp-1.5.0.tgz` собран, осталось `npm login` и `npm publish --access public`.
2. **Фоллбэк-пути PowerShell всё ещё ходят в UIA без отменяемого таймаута.**
   `Search-UiElements` и `Resolve-Target` остались на месте: нативный слой отдаёт
   только JSON, а паттернам нужны живые COM-объекты. Основные пути нативные, но если
   окно не нашлось или `uia-native.cs` не загрузился, идёт сюда.
3. **Таймаут нативного слоя проверен на искусственном зависании** (`RunSleep`), а не против
   реально замороженного окна. Живое зависание поймано со стороны сервера на окне Steam —
   circuit breaker отработал, но путь отравленного STA-потока против настоящего
   висящего COM-вызова не воспроизведён.
4. **`PrintWindow` в ветке OCR-снимка окна** — синхронный вызов в целевое окно, то есть
   тот же риск зависания, что у UIA. Обходится либо гардом, либо отказом от него.
5. **Roblox не проверялся ни разу.** Известный симптом из чужой сессии: клики не
   срабатывают. Версия: `C:\Users\DigitalJesus\AppData\Local\Roblox\Versions\version-02c37bc51a384b8f\RobloxPlayerBeta.exe`.
6. **`computer_polyline` двигает настоящий курсор, поэтому в автопрогон не входит.**

   процесс снимает `GetCursorPos` и `GetAsyncKeyState` каждые 8 мс и потом считает
   отклонение траектории от заданной ломанной.

## 4. Следующая задача (с чего начать)

Пункты 0 и 1 закрыты. Разрешение окна ушло на user32, нативный слой получил вход по
готовому HWND, а поиск элемента вместе с действием переехал на STA-поток. Замеры и
разбор причины лежат в коммитах про user32 и про ActJson.

**Что осталось медленным.** `computer_windows` отдаёт список окон примерно за 3 с под
нагрузкой: он по-прежнему перебирает верхний уровень через UIA, потому что
`EnumWindows` даёт 70 окон вместо 16 и насыщен служебными. Это сознательный размен,
и он описан в README. Если понадобится, правильный путь тот же, что и для чтения:
`EnumWindows` для заголовков, `FromHandle` для геометрии.

**Открытым остаётся пункт про возврат живого COM-объекта.** Раньше он был главным
блокером, теперь почти снят: `invoke` и `set_value` целиком уехали в нативный слой
и PowerShell больше не держит UIA-объектов. Что всё ещё идёт из PowerShell:
`Resolve-Target` (используется как фоллбэк, когда окно не нашлось или нативного
слоя нет) и сам `computer_find` в фоллбэке. Если фоллбэк убрать нельзя, оставить
как есть и не трогать.

**Ловушка, на которую уже наступали:** `@($ch, $depth + 1)` в PowerShell
разбирается как `($ch, $depth) + 1`. Пара всегда получалась из трёх элементов,
глубина обхода была 0, и `maxDepth` не ограничивал обход ни разу за историю
проекта. Пары собираются через `New-Object object[] 2`. Второй момент: в
PowerShell `ControlType` элемента читается как `Pane`, а в C# из того же handle
приходит верный `Button`, поэтому фильтр по типу в PowerShell-пути может не
сойтись. Именно поэтому поиск уехал в C#, а не остался в PowerShell с новым
корнем.

Не браться за DXGI-захват: он ломает главную фичу (ноль бинарных зависимостей).
Инструментов уже 46, новые добавлять только вместе с замером и сценарием в `smoke.mjs`:
инструмент без сценария через месяц никто не вспомнит, что он ломается.

**Что ещё не сделано из заимствованного у `sbroenne/mcp-windows`:** хелперы открытия и
сохранения файлов решено не брать (они завязаны на английскую Windows), .NET-зависимость
тоже: она убивает главное свойство проекта, ноль бинарных зависимостей.

## 6. Архитектура в двух абзацах

MCP-клиент говорит по stdio с `server.mjs`. Тот держит один долгоживущий воркер
`worker.ps1` (обмен построчный, ответы в base64 — иначе кириллица ломается на кодовой
странице консоли) и сам же держит CDP-клиент для браузера. Воркер внутри себя
разделяется на три слоя чтения: UI Automation (нативный, STA) → MSAA через `oleacc`
(автоматически, если UIA вернула пусто) → OCR на движке `Windows.Media.Ocr`. Ввод идёт
напрямую через `SendInput` / `mouse_event` / `SetCursorPos`, минуя PowerShell-обвязку.

Ключевое архитектурное решение, из которого следует всё остальное: **у слоя чтения
должна быть отменяемость**. COM-вызов в зависшее окно не возвращается никогда, поэтому
обход уехал на STA-поток с таймаутом и перерождением, а поверх него в сервере стоит
circuit breaker, который после зависания блокирует это окно, чтобы не повторять простой.

## 7. Правила работы с проектом

1. **Не двигать курсор пользователя.** Прямой запрет: он раздражает, когда работает.
   В `smoke.mjs` блок «руки» отсутствует намеренно. GUI-действия — только по явной
   просьбе пользователя и с предупреждением.
2. **Каждое утверждение проверять замером, а не чтением кода.** За четыре раунда
   ревью примерно половина «критичных» находок оказывалась ложными. Замер, команда,
   вывод — обязательны.
3. **Проверять вживую, на настоящем приложении.** Живой прогон нашёл больше дефектов,
   чем любой аудит: Paint (клик без движения), CS (`rawinput` не существует), CDP
   (`browser_start` терял url), окно Steam (зависание UIA).
4. **Перед коммитом:** `node --check server.mjs`, проверка парсинга `worker.ps1`,
   `node smoke.mjs`, затем `git status` глазами.
5. **Релиз:** поднять версию в `package.json` **и** в `server.mjs` (`McpServer`), закоммитить,
   `git tag -a vX.Y.Z -m "..."`, `git push origin main --follow-tags`. Версии в двух местах
   уже рассинхронизировались один раз — проверяй оба.

## 8. Мои ошибки — не повторять

- **`.NET`-методы не уважают текущий каталог.** `[System.IO.File]::ReadAllBytes('file')`
  из bash-обёртки ищет в `C:\Users\DigitalJesus\.minimax\workspace`, а не в каталоге `cd`.
  Хуже: `$txt` становится `$null`, и следующий
  `WriteAllText((Resolve-Path ...).Path, $txt, ...)` **успешно обнуляет файл** — так был
  потерян `server.mjs` до `git checkout`. Всегда брать абсолютный путь и проверять ввод.
- **`Set-Content -Encoding UTF8` в PS 5.1 пишет BOM.** В `.mjs` и `.json` он ломает
  Node (`Invalid or unexpected token` на shebang). Для `worker.ps1` BOM обязателен: без него
  PowerShell 5.1 читает файл как ANSI и ломает кириллицу.
- **Никогда не переписывать файл с кириллицей через `Set-Content`.** На версии 1.5.0 так
  сломался `server.mjs`: `Get-Content -Raw | Set-Content -Encoding ascii` заменил русские
  буквы в описаниях тулов и проверках ошибок на знаки вопроса, `node --check` упал на
  битом регулярном выражении, и битый коммит уже ушёл на GitHub. Правило: файлы с
  кириллицей менять только через Edit/Write либо
  `[System.IO.File]::WriteAllText($path, $text, (New-Object System.Text.UTF8Encoding($false)))`.
- **`worker.ps1` править только через Edit/Write.** Через `WriteAllBytes` без BOM он
  перестаёт парситься, а через `Set-Content` — получает BOM дважды.
- **Индексация узлов дерева.** `$x['name']` работает для `ordered`-хэштегов PowerShell и
  **молча даёт `$null`** для `PSCustomObject` из `ConvertFrom-Json`. На этом счётчики
  дерева объявляли полный результат пустым. Есть `Get-UiProp`.
- **Правка через regex по файлу вместо Edit** промахивается мимо сложных схем (экранировки
  `$`, кавычки) и тихо ничего не меняет. Сверять результат через `Select-String`.
- **Ложные «критичные» от ревьюеров.** Проверять замером; несколько раундов ревью были
  почти бесполезны, а вот прогон на живом окне дал больше за час.
- **`[Environment]::TickCount64` в PowerShell 5.1 не существует** и молча отдаёт
  `$null`, а не ошибку. На этом висел кэш `Get-UiCached`: проверка возраста была ложной
  всегда, кэш не протухал никогда, а ветки `wait_element` с таймаутом уходили в
  бесконечный цикл (24 нативных вызова за 12 с при бюджете 500 мс). Правильно:
  `Get-MonoMs` через `[Diagnostics.Stopwatch]::GetTimestamp()`.
- **Код ошибки рождался в PowerShell и умирал на границе.** `Fail 'ElementNotFound'`
  писал код в `$script:LastErrorCode`, воркер клал его в ответ, а `server.mjs` делал
  `entry.reject(new Error(msg.error))` и код просто выбрасывал. Этап «типизированные
  коды ошибок» считался готовым и проверялся на уровне PowerShell. Проверять
  машиночитаемую часть нужно **сквозным вызовом через MCP-клиент**, а не внутренним
  тестом.
- **Дельта требует протокола, а не одного параметра.** Каждый ответ `mode: auto`
  возвращает новый токен, и следующий вызов обязан нести именно его. Хелпер, который
  повторяет один и тот же аргумент N раз (как `timed()` в первом варианте
  `bench-full.mjs`), на втором прогоне получает полный вид и честно падает в 218-426
  раз дороже. Это не баг, но выглядит как баг, если не знать протокола.
- **`computer_bench`-подобные хелперы возвращают разное.** `checkTarget` в `smoke.mjs`
  отдаёт свой внутренний объект с полем `txt`, а `check` и `call` отдают сырой ответ
  MCP с `content[0].text`. Смешивать их в одном сценарии нельзя: разбор упадёт на
  `content[0]` и утащит за собой весь прогон.
- **Регистрация тулов теперь идёт через `reg()`, а не `server.registerTool()`.**
  Обёртка нужна для `DESK_DISABLE_TOOLS`. Если добавляешь инструмент и пишешь
  `server.registerTool` напрямую, отключение его не обойдёт.
- **`WORKER_TOOLS` и `UI_TOOLS` в `server.mjs` надо пополнять вместе с новым тулом.**
  Забытый `WORKER_TOOLS` даёт «неизвестный инструмент» в пачке, забытый `UI_TOOLS`
  незаметно обходит circuit breaker.
- **`JoinArray` не экранирует строки.** Заголовки таблицы, собранные как сырые строки,
  дают невалидный JSON без кавычек. Явно оборачивать в `J()`.
- **Компактный узел это позиционный массив, а не объект.** `$n.id`, `$n.name`,
  `$n.rect` на `Object[]` в PowerShell дают не поле, а символ по индексу, поэтому все
  узлы получали один ключ, а дельта по `compact: true` молча отвечала «ничего не
  изменилось» навсегда. Проверять разбор по форме узла, а не по наличию свойств.
- **PowerShell заворачивает вложенные массивы в PSObject при обращении к свойству.**
  `$o.windows` отдаёт элементы как `{value: [...], Count: N}`, и `$n[2]` на такой
  обёртке отдаёт список свойств. Лечится `[PSObject]::BaseObject($n)`. Это выглядит
  как «данные пришли сломанными», хотя на самом деле они пришли нормально, а ломается
  только чтение.
- **Условные слоты в компактном ответе врут.** Пока `value` и `text` дописывались
  только при наличии паттерна, позиция 6 у одного узла была значением, у другого
  текстом, а у третьего детьми. Легенда полей обязана соответствовать реальной
  позиции, иначе разбор по индексам едет.
- **Склеенный текст контейнера в подписи.** `TextPattern.DocumentRange` у контейнера
  отдаёт текст всех потомков, поэтому в сравнении версий корень окна меняется от
  любого изменения внутри и тянет за собой всё поддерево. Агрегатные поля в подписи
  версии не место.
- **Не измерять «полный ответ» суммой длин подписей.** Подпись это один узел, ответ
  это дерево с ключами и вложенностью, разница в разы. Сравнение враньё вырождало
  любую дельту в полный вид.
- **Ключи с заголовком окна надо ограничивать.** У базы дельт ключ это заголовок плюс
  параметры, а заголовок браузера меняется на каждую вкладку: агент, читающий
  страницы, создавал ключ на каждый заголовок и никогда не возвращался к старому.

## 9. Ловушки Windows (кратко, полный список в README)

- `KEYBDINPUT` — поля `ushort`, не `uint`. Объявишь `uint` — структура станет 32 байта
  вместо 24, `SendInput` молча ничего не сделает и не вернёт ошибку.
- PowerShell не имеет типа `[ushort]`, есть `[uint16]`.
- Статический C#-метод нельзя называть `Move` или `Wheel` — PowerShell не вызовет.
- `SendKeys` не умеет кириллицу, только `SendInput` с `KEYEVENTF_UNICODE`.
- `Add-Type` компилируется как **C# 5**: никакой интерполяции `$"..."`.
- `ConvertTo-Json -Depth` для дерева UI нужен ≥ 32, иначе режет и подставляет имя типа.
- COM-объекты `AutomationElement` кэшировать нельзя: протухают.
- **Paint игнорирует клик без движения** между нажатием и отпусканием. Лечится
  `computer_click { nudge: 1 }`.
- **В CS: Source cvar `rawinput` не существует.** Движок Source 2013 берёт `WM_MOUSEMOVE`,
  синтетический ввод мыши работает сразу. Причина «стреляет, но не вертится» — не raw input,
  а абсолютное наведение: в шутере курсор залочен в центре, нужен `computer_mouse_move`.
- В «Ожидании игроков» CS выкидывает с локального сервера и ввод блокируется целиком —
  легко сделать вывод «инструмент сломан». Глянуть таймер раунда и диалог Disconnect.

## 10. Рецепты, которые уже работают

```json
{"tool": "computer_mouse_move", "args": {"dx": 220, "dy": -40, "steps": 20, "stepMs": 8}}
{"tool": "computer_click", "args": {"x": 800, "y": 400, "nudge": 1}}
{"tool": "computer_click", "args": {"x": 640, "y": 360, "scale": 0.5}}
{"tool": "computer_browser_click", "args": {"selector": "#btn", "url": "example.com"}}
{"tool": "computer_verify_state", "args": {"title": "Paint", "expect": [{"selector": {"label_contains": "Сохранить", "role": "Button"}, "enabled": true}]}}
```

Переменные окружения: `DESK_UI_TIMEOUT_MS` (по умолчанию 8000), `DESK_UI_COOLDOWN_MS`
(90000), `DESK_UIA_BUDGET_MS` (внутри воркера, по умолчанию 6000), `DESK_DRY_RUN`,
`DESK_AUDIT`, `DESK_AUDIT_PATH`, `DESK_ALLOW_TITLES`, `DESK_DISABLE_TOOLS`. Бюджет
воркера меньше серверного намеренно: воркер должен успеть отдать внятный таймаут раньше,
чем сработает circuit breaker снаружи. Остальные четыре выключены по умолчанию и
включаются переменной, чтобы обычное поведение не менялось.

## 11. Где смотреть за изменениями

`CHANGELOG.md` — там каждая правка с причиной и замером, включая ложные гипотезы, которые
оказались неверными. Это самый плотный источник контекста в репозитории. `git log --oneline`
и `git show <hash>` дают историю решений. История чатов в памяти агента
(`agents/mavis/memory/MEMORY.md`) описывает ещё четыре раунда ревью и живые прогоны.
