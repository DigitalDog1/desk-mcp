# desk-mcp: полное руководство для продолжения работы

Прочитай этот файл целиком перед тем, как что-то менять. Он написан так, чтобы
работать без доступа к истории прошлой сессии. Детали и ловушки, на которые ушли
дни, лежат в `HANDOVER.md`; здесь только то, без чего следующий шаг будет сделан
неправильно.

---

## 1. Что это

MCP-сервер управления рабочим столом Windows. Читает интерфейс через UI Automation с
откатом на MSAA и OCR, действует мышью и клавиатурой через WinAPI и SendInput, отдаёт
агентам 46 инструментов. Работает без единой бинарной зависимости: Node плюс
PowerShell, который и так есть в системе. `npx -y desk-mcp` и всё.

Репозиторий: `C:\Users\DigitalJesus\.minimax\workspace\desk-mcp`, GitHub
`DigitalDog1/desk-mcp`, лицензия Apache-2.0, версия 1.5.0.

## 2. Быстрый старт

```bash
npm test              # автопрогон: 75-79 проверок, ноль провалов
npm run check:docs    # README.md и README.ru.md описывают одно и то же
npm run bench:full    # стоимость чтения окон живьём, с разделом «где проигрываем»
node examples/demo.mjs   # полный агентский сценарий на демо-окне, 10 шагов за 2.2 с
```

Окно для ручных проверок запускается через `Win+R`:
`powershell -NoProfile -ExecutionPolicy Bypass -STA -WindowStyle Hidden -File "...\examples\demo-app.ps1"`.
Из агентской сессии окна на десктоп не попадают, нужен именно `Win+R`.

## 3. Устройство

Три файла несут всё, остальное обвязка.

- **`server.mjs`** (Node): MCP-сервер, схемы инструментов, circuit breaker, пачка
  вызовов, CDP-клиент для браузера, режимы безопасности. Правки здесь видны агентам
  **только после перезапуска сервера**.
- **`worker.ps1`** (PowerShell 5.1): P/Invoke, MSAA, OCR, PrintWindow, дельты,
  диспетчер инструментов. Файл обязан остаться в UTF-8 **с BOM**, иначе PowerShell 5.1
  прочитает его как ANSI и сломает кириллицу. Воркер перезапускается сам, поэтому
  правки в нём видны сразу после рестарта воркера.
- **`uia-native.cs`** (C# 5, компилируется через Add-Type): STA-пул, обход дерева с
  отменяемым таймаутом, действия, выбор, таблицы. Именно C# 5: никаких интерполяций
  `$"..."`, никаких `async` в этом файле.

Путь вызова: агент → `server.mjs` → (для UIA-инструментов) `callUi` с breaker →
`worker.ps1` → `uia-native.cs` → UI Automation → назад. Инструменты, ходящие в UIA,
перечислены в `UI_TOOLS`; всё, что не в этом списке, идёт через `worker.call`.

Регистрация инструментов идёт через обёртку `reg()`, а не напрямую
`server.registerTool`: обёртка нужна для `DESK_DISABLE_TOOLS`. Написать
`server.registerTool` напрямую значит обойти отключение инструмента.

## 5. Ключевые решения, которые не надо переигрывать без причины

- **Ноль бинарных зависимостей.** Любая попытка добавить .NET или нативный модуль
  ломает главную фичу проекта. DXGI-захват поэтому тоже отвергнут.
- **Дельты привязаны к дескриптору окна, а не к заголовку.** Заголовок живого окна
  меняется сам, и база по заголовку плодила мусор.
- **`mode: full` не обновляет базу дельт.** Осмотр всегда честный.
- **Дельта, которая вышла бы не меньше полного ответа, не отдаётся.** Сравнение идёт
  с настоящим JSON полного ответа, а не с суммой длин подписей.
- **Отказ на `enabled: false` строгий.** `InvokePattern` на заблокированном элементе
  в Windows возвращается довольным и не делает ничего, тихо гасить это нельзя.
- **`notSelected` это отдельный статус**, а не ложный успех.
- **Код ошибки дублируется в `$script:LastErrorCode`**, потому что PowerShell теряет
  тип исключения, выброшенного из скриптблока.
- **Заголовки таблицы читаются по соглашению**: у `TablePatternInformation` в .NET нет
  признака «эта строка заголовок».

## 6. Как проверять, а как не проверять

**Проверять результат, а не читать код.** Каждый этап закрывается замером на живой
системе: байты файла, пиксели в PNG, курсор и состояние кнопки отдельным сэмплером,
ответ сквозного MCP-вызова.

**Вещи, которые нельзя проверить без живого окна:** зависание UIA (нужно реально
зависшее окно), срабатывание breaker'а (нужна целенаправленная порча), отказ на
заблокированном элементе, поведение в чужом приложении.

**Ложная посылка, которая уже стоила дней:** «ответ ok» не значит «сработало».
Дважды подряд фича проходила тесты и не работала: коды ошибок не доходили до клиента,
а дельта на компактных деревьях всегда говорила «ничего не изменилось».

## 7. Ловушки, которые уже стоили времени

Полный список с разбором в `HANDOVER.md`, раздел 8. Самые дорогие:

- **Компактный узел это позиционный массив.** `$n.id` к нему даёт не поле, а символ
  по индексу. Все узлы схлопывались в один ключ, и дельта была мертва всегда.
- **PowerShell заворачивает вложенные массивы в PSObject** при обращении к свойству:
  узел приходит как `{value: [...], Count: N}`. Лечится `[PSObject]::BaseObject($n)`.
- **`@($null).Count` равен 1, а не 0.** Проверка «есть ли дети» через `Count` считала
  лист контейнером.
- **Слоты в компактном ответе были условными**, позиция 6 была то значением, то
  текстом, то детьми. Теперь слоты всегда на месте.
- **Склеенный текст контейнера** (`TextPattern` отдаёт текст всех потомков) в подписи
  дельты делал корень окна вечно изменённым.
- **`[Environment]::TickCount64` в PowerShell 5.1 не существует** и молча отдаёт
  `$null`. Из-за этого кэш дерева не протухал никогда.
- **`\w` и `\b` в JavaScript не покрывают кириллицу.** Две проверки молча проходили
  мимо цели, пока это не выяснилось на негативном тесте.
- **Регулярная выдача кодов снимала BOM у `worker.ps1`.** Правь только через Edit или
  Write, либо через .NET с `UTF8Encoding($true)`.
- **`checkTarget` в `smoke.mjs` возвращает внутренний объект с полем `txt`**, а `call`
  и `check` возвращают сырой ответ MCP с `content[0].text`. Смешивать нельзя.
- **Заголовок окна протухает.** Агент, держащий заголовок между вызовами, получает
  отказ или, что хуже, молча читает другое окно. Дескриптор из `computer_windows`
  переживает это, и его надо использовать.

## 8. Что заблокировано не мной

- **`npm publish` требует владельца**: `npm login` и `npm publish
  desk-mcp-1.5.0.tgz --access public`. Версия 1.5.0 собрана и не вышла.
- **Правки в `server.mjs` не видны агентам, пока сервер не перезапущен.** Если агент
  рапортует, что новой функции нет, проверь версию сервера раньше, чем искать баг.

## 9. Что дальше, по приоритету

**Первое: замер там, где координаты не угадываются.** Это главный открытый вопрос
проекта. Пока нет ни одной задачи, где структурное чтение выиграло, любое утверждение
о преимуществе не подкреплено. Задача должна быть одна: окно с сотней похожих
элементов, где цель не находится глазами, с независимой проверкой результата.
Подготовка: в `C:\Windows\Fonts` 516 файлов, из них 246 `.ttf`, три самых больших
`ttf`: `simsunb.ttf`, `malgun.ttf`, `malgunbd.ttf`. Это проверено PowerShell'ом и
подходит как эталон.

**Второе: честная формулировка вместо недоказанной.** Если замер на сложной задаче мы
выигрываем, README должен продавать структуру. Если проигрываем, README должен продавать
то, что действительно есть: нулевая установка, устойчивость к зависшим чужим окнам,
слои безопасности. Недоказанное обещание дороже признания.

**Третье: элемент по идентификатору, а не по имени.** Сейчас `invoke` по имени каждый
раз ищет заново, и пересозданная кнопка с тем же именем получит клик. У конкурента
`sbroenne/mcp-windows` элементы адресуются `elementId` из `find`, и подмена элемента
ломает ссылку, а не перехватывает действие. Это правка на полдня и настоящий класс
защиты, а не удобство.

**Четвёртое, по убыванию:** частичные ответы (`truncated`, `searchIncomplete`, чтобы
агент знал, где данных может не хватать, вместо молчаливого обрезания по
`maxElements`); `requireUnique` и поиск по регулярке в `computer_find`; `inputMode` в
`computer_type` для React и Electron, где приложение должно увидеть клавиатурное
событие, а не значение из `ValuePattern`.

## 10. Чего не делать

- **Не добавлять инструмент без замера и без сценария в `smoke.mjs`.** Инструмент без
  сценария через месяц никто не вспомнит, что он ломается.
- **Не гнаться за конкурентом списком фич.** Их 104 звезды и опубликованные замеры на
  настоящих моделях, у нас пока нет ни того, ни другого. Список фич без измерений
  проигрывает.
- **Не измерять то, что невыполнимо.** Рукавка скриншотов в первом прогоне получила
  список без `computer_drag`, задача оказалась нерешаемой, и «победа» структурного
  чтения в три раза была измерением моей же ошибки. Ограничение должно быть выполнимым.
- **Не переписывать `worker.ps1` через `Set-Content`.** Только Edit/Write или .NET с
  явной кодировкой, BOM обязателен.
- **Не коммитить непроверенное.** Замер, потом коммит, потом push.
- **Не править один README из двух.** После правки документации гонять
  `npm run check:docs`.
- **Не мерить стоимость чтения и называть это стоимостью задачи.** Это разные вещи, и
  в первой версии замера это было причиной ложного вывода.

examples/demo.mjs      демо как агентский сценарий через MCP-клиент
docs/benchmark-tasks.md     замер на живых задачах, метод и отрицательный вывод
CHANGELOG.md           все находки с замерами и причинами, главный источник контекста
HANDOVER.md            состояние, открытые пункты, полный список ловушек
CONTRIBUTING.md        грабли, которые не видно по коду
README.md / README.ru.md    документация, синхронность проверяется автоматически

Место, где стоит начинать чтение кода: `Invoke-Tool` в `worker.ps1` (диспетчер всех
инструментов) и `reg` в `server.mjs` (регистрация и схемы). Логика дельт в
`Compare-Tree`, `Get-NodeKey`, `Get-NodeSignature`, `Expand-Node`.
