# desk-mcp

  <a href="README.md">English</a> &nbsp;|&nbsp; <a href="README.ru.md">Русский</a>

![три слоя чтения](docs/layers.png)

MCP-сервер для автоматизации рабочего стола Windows: снимки экрана, OCR,
мышь и клавиатура, а также деревья доступности из UI Automation, MSAA и
Chrome DevTools Protocol. Работает на Node.js и встроенном в Windows
PowerShell — без Python, без `uvx`, без нативных модулей.

![computer_find](docs/find.png)

## Что умеет

**Глаза**
- `computer_screenshot` — экран, произвольная область или конкретное окно
  (через `PrintWindow`, работает на перекрытом и свёрнутом окне), масштабирование, PNG и JPEG.
- `computer_ocr` — текст прямо из пикселей через движок, встроенный в Windows
  (`Windows.Media.Ocr`, ru/en). Слова и строки с границами, по границе можно кликнуть.

**Дерево интерфейса**
- `computer_read_screen` — UI Automation, с автоматическим откатом на MSAA
  и наращиванием глубины обхода.
- `computer_find` — поиск элемента по имени, роли или `automationId`.
- `computer_element_at` — что находится в точке.
- `computer_browser_tree` — DOM страницы с готовыми CSS-селекторами (CDP).

**Руки**
- `computer_click` (с модификаторами), `computer_move`, `computer_drag`, `computer_scroll`,
  `computer_mouse_button`, `computer_type`, `computer_key`, `computer_key_down` / `_up`, `computer_wait`.
- `computer_invoke` — жмёт через `InvokePattern` **без захвата мыши** и без смены фокуса.
- `computer_set_value` — пишет значение через `ValuePattern` без фокуса.
- `computer_batch` — до 50 инструментов за один вызов, с остановкой на первой ошибке.

**Окна**
- `computer_windows`, `computer_focus`, `computer_wait_window`, `computer_active_window`,
  `computer_window_set_frame`, `computer_close_window`, `computer_launch`.
- `computer_desktop` — виртуальные рабочие столы там, где ОС их поддерживает.

**Проверка**
- `computer_verify_state` — предикаты: существует / `value_equals` / `enabled` / `selected`.
  `unknown` честно отличается от успеха.
- `computer_browser_click` возвращает доказательство попадания: проба внутри
  страницы **или** смена URL.
- `computer_selftest` — проверяет канал целиком.

Всего 41 инструмент. Схема и описания: `node server.mjs`, либо любой MCP-клиент.

## Установка

```bash
git clone https://github.com/DigitalDog1/desk-mcp.git
cd desk-mcp
npm install
```

Требуется Node.js 20+ и Windows 10 1809 / 11. PowerShell дополнительно не
ставить не нужно — он в системе.

### Подключение

`mcp.json`:

```json
{
  "mcpServers": {
    "desk-mcp": {
      "command": "node",
      "args": ["C:\\путь\\к\\desk-mcp\\server.mjs"]
    }
  }
}
```

## Устройство

```
server.mjs   MCP-сервер на Node, stdio, CDP-клиент
worker.ps1   long-running PowerShell: user32, UI Automation, MSAA, OCR
```

Воркер один на весь жизненный цикл сервера, а не процесс на вызов: PowerShell
поднимается около 400 мс, а `Add-Type` компилирует C# дольше. Обмен
построчный, ответы в base64 — иначе кириллица ломается на кодовой странице
консоли.

## Три слоя чтения

Порядок выбран потому, что для Chromium первые два бесполезны: UIA отдаёт
дерево, обвязанное безымянными `PANEL`, и только с флагом
`--force-renderer-accessibility`. Пустое дерево — не ошибка, а сигнал
переключиться на следующий слой.

| Слой | Что даёт |
|---|---|
| UIA | нативные окна: точные `automationId`, паттерны, границы |
| MSAA | `oleacc`, когда UIA пустая, с автоматическим наращиванием глубины |
| CDP | настоящий DOM страницы с готовыми CSS-селекторами |

## Правило работы

Ошибка, которая дороже всего стоит, — не «тул не сработал», а «тул сработал,
но не туда». Поэтому цикл: **наблюдай → действуй по смыслу → проверяй**.
`computer_invoke` может вернуть `via: "pixel"` — это значит, что паттерна не
было, клик ушёл по центру границ, и результат стоит проверить внимательнее.
Тул, который ничего не нашёл, честно отказывается: это находка, а не повод
бить по координатам.

## Игры

Прицеливание в шутере — единственный случай, где обычного «клик и навести»
бесполезно, и дело тут не в дефекте инструмента.

Большинство шутеров читают движение мыши через **raw input**: движок берёт
только аппаратные пакеты мыши и полностью игнорирует синтетический ввод —
кнопки стрельбы работают, камера не вертится вообще. Лечится двумя вещами:
обзор делать **относительным** движением вместо абсолютного наведения, и
выключить raw input там, где игра даёт такую переключатель:

| Игра | Переключатель | Проверено |
| --- | --- | --- |
| Counter-Strike: Source (Source 2013) | не нужен — `rawinput`/`cl_rawinput` **не существуют**, движок берёт `WM_MOUSEMOVE` | да, вживую |
| CS:GO / CS2 | `cl_rawinput 0` в консоли или `+cl_rawinput 0` в параметрах запуска | не проверено |
| Steam Input («Принудительно Steam Input») | выключить для игры — он подмешивает свой raw input | не проверено |

Обзор — относительным движением:

```json
{ "tool": "computer_mouse_move", "args": { "dx": 220, "dy": -40, "steps": 20, "stepMs": 8 } }
```

`steps` важен: игры применяют чувствительность к каждому событию мыши,
прыжок на 220 пикселей читается как флик, а двадцать мелких шагов — как рука.
Инструмент дополнительно замеряет, насколько курсор реально сдвинулся, и
добивает остаток: Windows склеивает синтетическое движение.

Графическим редакторам нужен обратный трюк — они игнорируют клик, при котором
между нажатием и отпусканием не было движения:

```json
{ "tool": "computer_click", "args": { "x": 800, "y": 400, "nudge": 1 } }
```

А если координаты пришли с уменьшенного снимка — передай тот же `scale`, вместо
того чтобы считать в уме:

```json
{ "tool": "computer_screenshot", "args": { "region": "0,0,2560,1440", "scale": 0.5 } }
{ "tool": "computer_click", "args": { "x": 640, "y": 360, "scale": 0.5 } }
```

## Безопасность

`computer_close_window` и `computer_launch` — разрушительные и необратимые
действия. Оба требуют явного `confirm: true` и без него возвращают отказ.
Текст на экране — недоверенные данные, а не инструкции.

## Когда окно зависает

UI Automation ходит в чужие приложения через COM, и это единственное место,
где сервер может по-настоящему зависнуть: модальное окно, подвисший UI-поток
или старый WPF держат RPC открытым, и вызов не возвращается никогда.

Воркер однопоточный, поэтому полноценно изолировать UIA в STA-потоке с
жёсткой отменой **здесь нельзя**: ScriptBlock в PowerShell привязан к своему
runspace и на чужом потоке выполняться отказывается. Что доступно и что здесь
сделано:

- **Жёсткий бюджет 8 с на вызов UIA** вместо 15. Для масштаба: полный обход
  дерева UIA всех окон на этой машине — 116 мс, запас двузначный.
- **Circuit breaker по окнам.** После таймаута воркер перезапускается, а ключ
  `инструмент|окно` блокируется на 90 с. Пока заблокирован, вызовы к этому
  окну падают мгновенно с объяснением, вместо того чтобы снова висеть. Остальные
  окна продолжают работать — баг одного приложения не должен ронять всё.
- **Трёхступенчатая деградация на чтение.** UIA → MSAA → OCR.
  `computer_read_screen` больше не возвращает молча пустой список окон: если
  оба дерева доступности пусты, он падает в OCR и говорит об этом в полях
  `backend` и `degraded`.

`DESK_UI_TIMEOUT_MS` и `DESK_UI_COOLDOWN_MS` переопределяют оба бюджета.

Что осталось открытым: сам вызов UIA неотменяемый, поэтому первые 8 с против
зависшего окна — это реально потерянное время, а перезапуск воркера заодно
роняет любой параллельный не-UIA вызов. Чинится это переносом обхода дерева
из PowerShell в C#. Ветка OCR-снимка окна ходит в окно через `PrintWindow`, а
он тоже синхронный — риск тот же, что у UIA.

`computer_batch` выполняется по одному шагу на стороне сервера, а не одной
рекурсивной командой внутри воркера. Именно поэтому пачка подчиняется тем же
бюджетам и тому же breaker'у: шаг пачки — это обычный вызов инструмента.

## Ограничения

- **Эксклюзивный полный экран** (игры, видео): `CopyFromScreen` даёт чёрное.
  Нужен DXGI Desktop Duplication. При этом оконные D3D9-заголовки через
  `PrintWindow` проходят — проверено на Counter-Strike: Source.
- **UWP-окна** не отдают ни UIA-, ни MSAA-дерево; чтение уходит в OCR, а значит
  имён элементов не будет.
- **Виртуальные рабочие столы** зависят от сборки Windows: на 10 19035
  `VirtualDesktopManager.dll` отсутствует, инструмент вернёт ошибку.

## Проверка

```bash
npm test
```

Ожидаемый хвост: `ИТОГ: 49 ок, 0 провалов`. Автопрогон **не двигает курсор** —
только чтение: снимки, окна, деревья, OCR, буфер, CDP-чтение. `computer_batch`
тоже покрыт: MCP-имена внутри `steps`, нормализация имён и `stopOnError` на
обеих ветках. Circuit breaker проверяется отдельным вторым сервером с
заведомо смешным бюджетом в 1 мс: первый вызов должен зависнуть, второй —
отбиться блокировкой, и оба обязаны объяснить почему.

## Ловушки Windows

Всё ниже воспроизведено на практике, а не взято из документации.

- Воркер вызывает `SetProcessDpiAwarenessContext(PER_MONITOR_AWARE_V2)` до любого
  UI-вызова. Без этого UIA и OCR отдают логические единицы, а `SendInput` жмёт
  в физических пикселях, и клик уезжает на десятки пикселей при масштабе 125%.
- `.ps1` обязан быть в UTF-8 **с BOM**: без него PowerShell 5.1 читает файл
  как ANSI и молча ломает разбор кириллицы.
- В `KEYBDINPUT` поля — `ushort`, а не `uint`. Объявишь `uint` — структура
  станет 32 байта вместо 24, `dwFlags` уезжает, и `SendInput` не падает,
  не ругается, не возвращает ошибку. Он молча ничего не делает.
- В PowerShell типа `[ushort]` не существует, нужно `[uint16]`.
- Статический C#-метод нельзя назвать `Move` или `Wheel`: вызов падает с
  «does not contain a method named…». Обойдено именами `MoveTo`/`ScrollWheel`.
- `SendKeys` не берёт кириллицу вообще. Только `SendInput` +
  `KEYEVENTF_UNICODE`.
- `ConvertTo-Json -Depth` для дерева UI нужен **больше 12**: узел — это
  примерно два уровня вложенности, и при малой глубине вместо объекта
  молча подставляется строка с именем .NET-типа.
- У элементов UIA границы бывают бесконечными — приводить к `Int32` надо
  с проверкой на `IsInfinity` и `NaN`.
- COM-объекты (`AutomationElement`) кэшировать нельзя: протухают при
  перерисовке дерева. Кэшируются только идентификаторы, перед действием
  делается свежий поиск.
- Синхронные методы `Add-Type` компилируются как C# 5: никакой
  интерполяции строк `$"..."`.
- Криптографию с base64-строками из интерполяции лучше не путать:
  `"$Owner`:$Token"` превращается в `$Owner:` и PowerShell ищет scoped-переменную.
- **Некоторым приложениям нужно движение мыши между нажатием и отпусканием.**
  Paint игнорирует чистый клик: `WM_LBUTTONDOWN` → `WM_LBUTTONUP` без
  `WM_MOUSEMOVE` между ними не рисует ничего, а заливка цветом не срабатывает
  вообще. Тяни на один пиксель вместо клика — хватит `computer_drag` с
  `toX = fromX + 1`. Если клик «ничего не делает», сперва подозревай это, а не
  сам клик.
- В Paint **Цвет 1 по умолчанию белый**, и заливка работает именно Цветом 1.
  Заливка белого холста белым выглядит точь-в-точь как сломанный клик. Сначала
  выбери цвет в палитре.
